# Project rules

Read by every person and coding agent before changing anything. Details: [CONTRIBUTING.md](CONTRIBUTING.md) (workflow, ownership, conflicts), [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (seams), [docs/SETUP.md](docs/SETUP.md) (run and test).

## Objective
Build a Unity VR prototype for HackTX: eye-signal capture -> deterministic metrics -> Gemini wellness summary -> a personalized, prebuilt relaxation scene. Ship one reliable forest demo with optional squirrels before adding more environments.

## Development
- Use Unity/C# (6000.6.7f1) for VR and Python/FastAPI with the Google Gen AI SDK for the backend. Keep the Gemini key on the backend.
- Keep capture, metrics, AI interpretation, and scene configuration separate; they meet only at the seams in `docs/ARCHITECTURE.md`. Change shared JSON contracts only through a contract PR that updates schema, fixtures, C# DTOs and Pydantic models together.
- Implement one acceptance criterion at a time; validate changed behavior and report exactly what ran. Headset-only checks must be identified when unavailable.

## Working agreement (prevents merge conflicts and lost work)
- **Branches:** start every task from the latest `origin/dev` on a short-lived `feat/`, `fix/`, `docs/`, `test/` or `chore/` branch; open a PR into `dev`. `main` is the demo-ready snapshot, updated only by a `dev` -> `main` PR after the full check.
- **Merge method:** always "Create a merge commit". Never squash or rebase-merge a branch that anyone has pulled or merged elsewhere.
- **Stay current:** merge `origin/dev` into your branch at least every few hours and before asking for review. Never force-push a shared branch.
- **Ownership:** edit only your area (table in `CONTRIBUTING.md`). Touching another owner's file needs their OK in the PR; two people never edit the same scene, prefab or file at the same time.
- **Shared files are append-only:** do not rewrite README, `docs/SETUP.md`, `docs/ARCHITECTURE.md`, `docs/PROJECT_PLAN.md`, `stages.md`, `AGENTS.md` or `CONTRIBUTING.md` in a feature PR; add your own `docs/<AREA>.md` and at most a one-line link. The integrator updates the shared status text.
- **Unity:** close the editor before `git pull`/`git switch`. Commit every asset with its `.meta`; never hand-edit GUIDs. `Assessment.unity` and `UI/Prefabs` are generated by `App > Build Assessment Scene`: change the builder, not the files.
- **Before a PR:** run the checks for your area (commands in `docs/SETUP.md`) and the secret scan in `CONTRIBUTING.md`.

## Agents may
- Inspect, implement, refactor within the assigned scope, update docs, and run local checks.
- Create local branches and draft PRs for requested changes; request a teammate's review.
- Add clearly labeled synthetic fixtures and deterministic offline fallbacks.

## Agents must not
- Merge PRs, push directly to `main` or `dev`, force-push shared branches, or discard teammates' changes without explicit authorization.
- Resolve a merge conflict by taking one whole side ("accept ours/theirs") without reading both; never delete another owner's file to make a merge pass.
- Buy assets, enable billing, increase spending limits, or deploy publicly without explicit authorization.
- Commit credentials, `.env`, `unity/Assets/Resources/DevAgentSettings.asset`, identifying eye data, raw eye images, recordings or personal reports; transmit real eye data or participant free text to Gemini.
- Diagnose conditions, prescribe treatment, invent measurements/accuracy, call the indicator a "fatigue score", or describe a demo score as clinically validated.
- Represent head gaze, missing tracking, synthetic/replay data, or cached/fallback AI output as live eye measurements or live AI.
- Execute model-generated code, arbitrary tools, asset URLs, or scene scripts. Apply only validated, allowlisted scene settings.
- Replace the working offline demo with an untested live-generation dependency.

## Done
Acceptance criteria met; checks recorded (what ran and what did not); data/AI provenance visible; offline demo still works; the PR merges cleanly into the current `dev`; a human teammate approves before merge.
