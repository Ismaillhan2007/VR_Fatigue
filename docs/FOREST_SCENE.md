# ForestDemo: assets, integration plan and hardware checks

## Role in the product

The forest is **one optional relaxation use case of the eye-tracking app**. The core outcome is an experimental health/fatigue wellness report, and users must be able to complete a report-only session without entering `ForestDemo` or selecting scene settings. Only an explicit participation choice should load/apply this experience; receiving a `SceneConfig` is not that choice. The current app still routes normal completion through Scene/Re-rating; see [objectives and implementation gaps](OBJECTIVES.md). The preparation status and asset checks below describe the original scene handoff, not completion of the report-only work.

Owner: environment and experience (`feat/forest-scene`). Status: **prepared without a Unity project**. Nothing here has been compiled, imported or run; the Unity project and version are created by the integration owner. The scripts in `unity/Assets/App/Relaxation/` are unverified until opened in the editor.

## 2. Curated Quaternius subset (starting list)

Calm temperate forest, no snow/autumn/dead/desert variants:

- Trees: `CommonTree_1..5`, `BirchTree_1..5`, 1-2 of `Willow_1..5` near water, `PineTree_1..3` sparingly for variety.
- Understory: `Bush_1..2`, `BushBerries_1`, `Plant_1..5`, `Grass`, `Grass_2`, `Grass_Short`, `Flowers`.
- Ground detail: `Rock_1..7`, `Rock_Moss_1..7`, `TreeStump`, `TreeStump_Moss`.
- Skip: all `*_Snow_*`, `*_Autumn_*`, `*_Dead_*`, `Cactus*`, `PalmTree*`, `Corn*`, `Wheat`, and no urban objects.

Placement rules: irregular spacing (jittered Poisson-style, no grid), random Y rotation, 0.85-1.2 uniform scale, a clear clearing around the camera, nothing closer than about 2.5 m to the viewer, rocks half-sunk into the ground, no floating or intersecting trunks. Mark trees/rocks static for baked lighting; reuse the same few materials so batching works.

## 3. HDRI plan (Quest Pro)

- A 4K equirectangular HDR is large at runtime (uncompressed it is tens of MB of GPU memory). Do not use the 4K EXR directly on the headset.
- Plan: import the EXR, downsize to about 1K-2K, set cubemap/skybox with compression, and use it for the skybox and baked ambient/reflection data. Prefer a baked ambient probe over realtime reflections.
- Check the actual imported resolution, format and memory in the Unity profiler / import inspector, and record them here. These numbers are **not yet known**.
- Fallback: a simple procedural/gradient skybox with the same fog tint.

## 4. Squirrel integration point

**Placeholder model (generated, not yet seen in an engine):** `unity/Assets/App/Squirrel/Squirrel.obj` + `.mtl` (about 3.4k triangles, sitting pose, roughly 0.39 m tall with tail, three flat materials `SquirrelFur`/`SquirrelBelly`/`SquirrelDark`, separate `Body` and `Tail` objects). Regenerate with `python tools/generate_squirrel.py`. Its mesh indices and bounds were checked by script, but it has not been rendered or imported; expect to adjust proportions and convert the materials to URP. To use: import the OBJ, make a prefab, add `SquirrelIdle` (it creates a tail pivot at runtime and eases a small tail sway/breathing in and out), and place the prefab under the anchor. If the real Rifat3D model is later downloaded by a person with access, swap it in behind the same anchor.

Anchor setup:

1. The forest scene contains an empty transform `SquirrelAnchor` assigned to `SceneConfigApplier.squirrelAnchor`.
2. A future squirrel is a separate prefab (own animator, short fixed idle/path, no chasing, kept at least 3 m from the viewer, never appearing suddenly nearby), added as a child of the anchor, so it does not require a scene edit.
3. `animals_enabled = false` deactivates the anchor. This always wins over any AI recommendation.
4. Optional motion components implement `IAmbientMotion` and are listed in `ambientMotionTargets`.

## 5. SceneConfig compatibility (unchanged contract)

`SceneConfig.cs` mirrors `contracts/v1/scene_config.schema.json` (currently in `feat/contracts-v1`); no fields were added or renamed. Behavior:

- Structurally invalid input (bad JSON, wrong `schema_version`/`scene_id`, unknown enum or particle, missing objects, more than 2 particles) -> saved preset. Out-of-range or non-finite numbers are clamped.
- `SceneConfigApplier` changes lighting (`day`/`sunset`, warmth, brightness), fog, four sound layers, particles, motion, orb and squirrel anchor, with gradual transitions for light and sound. `SetMuted` and `sound: silent` set `AudioSource.mute` immediately and bring layer volume to 0.
- `SceneConfigMapper` implements the chip -> `SceneConfig` rules from `docs/CONCEPT.md` 7.3, then applies explicit `Preferences`, then forces silence/animal-free choices last.
- Judgment call to confirm: the `want_quiet` chip caps `master_volume` at 0.2 (CONCEPT allows "silent, or 0.2"); only an explicit `Preferences.sound = silent` mutes entirely.
- The saved preset is `fixtures/scene_config_calm_forest_sunset.json` (copy it into the project as a `TextAsset` and assign it to `savedPresetJson`). The same values are the built-in `SceneConfig.CalmForestSunset()` fallback. If the two ever diverge, update both.
- Not implemented here: the confirmation/edit screen (another owner), and the pause/exit/mute UI. The applier exposes `SetMuted`; the UI wiring is a task for the scene.

## 6. Comfort and performance rules for the scene

Static camera, no locomotion, no shake, no flashing, no fast brightness steps (transitions are 2-3 s by default), no sudden objects near the viewer. Prefer baked lighting, static batching, shared materials; use LODs only if the imported models provide them; avoid realtime reflections, many transparent layers, dense particles and heavy post-processing.
