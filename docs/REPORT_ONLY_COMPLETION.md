# Report completion and optional relaxation (#16)

## Runtime behavior

The assessment/check-in produces the same experimental wellness report regardless of whether relaxation is chosen. The report shows measurements, baseline deviations, quality, limitations, safety and source/AI provenance. Its display no longer includes a scene preview or scene rationale.

- **Finish with report** moves Summary to Done. Done displays the report; it remains in memory until New session or Exit. This path does not select preferences, populate a scene handoff, load ForestDemo or create post-scene feedback.
- **Try optional relaxation** opens a separate preferences/preview panel. Returning to the report clears unconfirmed preferences. **Enter optional forest** is a second deliberate action; it alone starts loading the forest. Preferences are applied locally to the validated config without another backend/AI request.
- Scene participants may submit feedback or finish without it. The end screen includes after-scene values only when feedback was submitted. A forest that did not load does not count as participation and does not request feedback.
- A `stop_session` notice blocks the optional-relaxation choice but permits report completion and immediate Exit. Pause continues to block flow transitions.
- Explicit Exit clears the report and recordings as before. Restart also clears recordings, scene handoff and pending analysis. A response from a departed session cannot repopulate the report or change a new session's busy state. An in-flight scene load is unloaded if the participant left before it finished.

The required v1 `scene_config` and `scene_rationale` fields remain on the wire. They are used only in the optional preview/scene branch; no JSON contracts or packages/settings were changed.
